# T36d1 — Single-Job Worker Writer Client

Bounded leaf: `createWorkerWriterClient` implementing `WriterPort` backed by a dedicated Web Worker running `worker-host` / `worker-session`.

Files:

- `docs/handoffs/T36d1.md`

`createWorkerWriterClient(options: WorkerClientOptions): WriterPort`:
- Constructor options captured and validated entirely within `try` boundary; throwing getters or proxies fail static `CONFIG_INVALID` before adopting worker.
- Owns one native `WorkerEndpoint`; returns frozen `WriterPort` with strict lifecycle `fresh -> beginning -> ready -> appending -> ready -> finalizing -> terminal`.
- Exactly one pending operation; concurrent/out-of-order calls fail closed (`INTERNAL_ERROR`).
- Permanent terminal latching: first failure or closure permanently latches safe `ErrorCode`; late ERROR, CANCELLED, or crash events cannot overwrite initial outcome.
- Shared `startOperation` installs pending identity before signal/snapshot callbacks. Malformed signals fail `CONFIG_INVALID`; pre-aborts fail `OPERATION_ABORTED`. Fences prevent `postMessage` if reentrant getters abort.
- Bounded per-op cleanup: `timerId` owned by `PendingOp`. Old pending state detached and committed BEFORE external cleanup (`removeEventListener`). Reentrant aborts or next appends during cleanup cannot corrupt state or hang promises. Worker listeners removed with independent `try` blocks.
- Hostile proxy defense: `parseWorkerArtifacts` descriptor traps calling `client.abort()` are fenced before resolution/cleanup; no `TypeError` or raw throws.
- Lead correction: worker timeout deadline uses `FORMAT_SERIALIZATION_FAILED`, never resets on progress.
